# 같은 기기를 새 전파로 세지 않기 — 간편 화면 구조 설계

> 이 문서가 말하는 "간편 화면"이 지금 앱의 감독관 화면이다. 함께 언급되는 상세 분석 화면(비교·기기·수신·레이더·채널)과 저장 기록·보고서는 1.0.0 공개 전에 없앴다.

2026-11-16 · 상태: 승인 후 구현됨. 화면은 아래 스케치 대신 와이파이 칸과 블루투스 칸을 나눈 구조로 구현했다(`core/SignalGroups.kt`, `ui/GuardScreen.kt`).

## 왜 바꾸는가

감독관이 집에서 시험해 보니 아무것도 켜지 않았는데 "새 전파 50개"가 떴다. 무엇이 왜 세어지는지 알 수 없고, 처음으로 되돌리는 방법과 제대로 동작하는지 확인하는 방법도 보이지 않았다.

원인은 간편 화면이 전파를 **주소**로만 구분하기 때문이다.

- 블루투스 기기 대부분은 10~15분마다 주소를 바꾼다. 같은 기기가 새 전파로 다시 세어진다.
- 공유기 한 대가 주소를 여러 개 쓰고, 약한 것은 30초 측정에서 빠졌다가 나중에 잡힌다.
- 한 번 뜬 전파는 사라져도 개수에 남아 계속 쌓인다.

## 감독관이 원하는 것 (사용자가 말한 것)

- 빈 교실의 전파를 먼저 측정해 두고 제외한다.
- 같은 블루투스·와이파이가 주소가 바뀌었다고 새 전파로 뜨면 안 된다.
- 남은 전파에 가까이 갔을 때 더 세게 잡히는 것을 보기만 하면 된다.
- 휴대폰을 꺼서 제출하므로 시험 중 전파가 잡히는 것 자체가 확인 대상이다.

## 목표

1. 주소가 바뀌어도 "새 전파" 개수가 늘지 않는다.
2. 화면에는 지금 잡히는 것만, 센 순서로 보인다.
3. 처음으로 되돌리는 버튼이 감시 화면에 항상 보인다.
4. 실제 기기로 동작을 확인하는 순서가 앱 안에 있다.

## 하지 않는 것

- 상세 분석 화면(비교·기기·수신·레이더·채널)과 저장 기록·보고서는 지금처럼 주소 기준으로 둔다.
- 주소가 바뀌는 순간을 시간으로 이어 붙이지 않는다.
- 사람·좌석을 특정하거나 부정행위를 판정하지 않는다.

## 이렇게 되면 실패

- 같은 기기가 주소만 바꿨는데 새 전파로 알린다.
- 빈 교실에 없던 종류의 전파가 지금 잡히는데 "원래 있던 것"으로 숨긴다.

## 검토한 방법

| 방법 | 내용 | 장단점 |
| --- | --- | --- |
| 1. 생김새 + 동시 개수 (**선택**) | 주소 대신 이름·제조사·종류로 묶고, 빈 교실 때보다 동시에 더 많이 잡힐 때만 알린다 | 주소가 바뀌어도 늘지 않는다. 같은 종류를 맞바꾸면 구분하지 못한다 |
| 2. 세기만 | 제외는 주소로 하고 센 것만 보인다 | 가장 단순하나 가까운 기기가 주소를 바꾸면 다시 뜬다 |
| 3. 주소 교대 잇기 | 사라진 주소와 곧바로 나타난 주소를 같은 기기로 잇는다 | 같은 종류끼리도 구분하지만 패킷 누락·앱 공백에 끊긴다. 실기기 없이 맞추기 어렵다 |

사용자가 1번을 골랐다. "같은 기기가 새 전파로 인식되면 안 된다"를 직접 해결하고 걸어 다니며 세기를 보는 용도와 맞기 때문이다.

## 설계

### 생김새(묶음 기준)

- **블루투스**: 이름이 있으면 이름. 없으면 광고 회사 코드 + 대표 종류 단서(`hints.primary`). 둘 다 없으면 `종류 모름` 한 묶음.
- **와이파이**: 이름(SSID). 이름을 숨긴 것은 `이름 숨긴 와이파이` 한 묶음.

### 빈 교실 기록

- 묶음마다 "동시에 몇 개였는지"를 저장한다. 저장하는 순간 잡히고 있던 주소 수이며, 측정 중 잡혔지만 그 순간에는 없던 묶음은 1개로 친다.
- 측정 시간은 최소 2분, 그리고 와이파이 탐색이 2번 이상 끝나야 `빈 교실 기록 저장`이 켜진다. 남은 조건을 화면에 보여 준다.

### 시험 중 판단

- **와이파이**: 이름이 빈 교실 기록에 있으면 주소가 몇 개든 원래 있던 것. 다만 이름을 숨긴 와이파이는 이름이 같다는 근거가 없어 이 규칙을 쓰지 않는다. 빈 교실 기록의 주소와 나머지 다섯 자리(앞 5바이트 또는 뒤 5바이트)가 같은 주소는 같은 공유기로 보고 이름과 상관없이 원래 있던 것이며(`isSameAccessPoint`), 그렇지 않은 이름 숨김 와이파이는 모두 새 전파로 바로 알린다(`SignalGroups.kt`의 `wifi && key == HIDDEN_WIFI_KEY` 분기).
- **블루투스**: 묶음별로 지금 잡히는 주소 수(마지막 수신 15초 이내)를 센다. 빈 교실 개수 이하이면 원래 있던 것. 초과가 30초 넘게 이어지면 "늘어난 전파"로 알린다. 30초는 주소가 바뀌는 순간 옛 주소와 새 주소가 겹치는 것을 거르기 위함이다.
- 빈 교실에 없던 묶음은 잡히는 즉시 목록에 올린다. 30초 넘게 이어졌는지는 `SignalGroup.alert`에 담기지만 화면은 이 값을 읽지 않으므로, 목록에 오른 묶음은 모두 "새 전파" 개수에 센다.
- `나의 찾기 신호`는 전원을 끈 아이폰과 에어태그가 내는 신호라 꺼서 제출한 휴대폰 수만큼 잡힐 수 있다. 별도 줄로 개수만 보이고 알림은 하지 않는다.

### 화면

```
[1 빈 교실 기록 ✓] [2 시험 중 감시]

  늘어난 전파 2개            감시 중 · 3층 1실 · 12분

  ▮▮▮▮ 무선 이어폰 · AirPods Pro            바로 옆
  ▮▮▯▯ 켜져 있는 Apple 기기 · 원래 2 → 지금 3   중간
        (눌러서 3개 각각의 세기 보기)

  ▸ 멀리서 약하게 잡히는 것 4개
  ▸ 꺼 둔 아이폰·에어태그 신호 6개
  ▸ 원래 있던 전파 11종

  [빈 교실부터 다시 측정]        [감시 끝내기]
```

- 지금 잡히는 것만 센 순서로 보인다. 사라지면 목록에서 빠지고 누적 개수는 없다.
- 줄을 누르면 지금의 위치 찾기 화면(큰 막대 + 진동)이 열린다. 묶음 줄은 속한 주소를 각각 보여 준다.
- `확인함`은 주소가 아니라 묶음에 적용한다(주소가 바뀌어도 유지). 이름을 숨긴 와이파이만 예외로 주소마다 따로 뺀다(`acknowledgeKey`).
- `빈 교실부터 다시 측정`은 감시 화면에 항상 있고, 누르면 확인을 받은 뒤 빈 교실 기록과 목록을 비우고 1단계로 돌아간다. 저장된 과거 기록은 지우지 않는다.

### 동작 확인 순서

안내 버튼 안에 `제대로 잡히는지 확인하기`를 둔다. 빈 교실 기록을 저장한 뒤 차례로 해 본다.

1. 무선 이어폰 케이스를 연다 → 30초쯤 뒤 목록에 뜨고, 다가가면 막대가 늘어난다.
2. 다른 휴대폰의 핫스팟을 켠다 → 와이파이 탐색 주기 때문에 최대 1분쯤 뒤 뜬다.
3. 15분 넘게 둔다 → 개수가 늘지 않아야 한다.
4. `빈 교실부터 다시 측정`을 누른다 → 1단계로 돌아간다.

자동 테스트: 같은 생김새의 주소가 바뀌어도 늘지 않음, 같은 생김새가 하나 더 잡히면 늘어남, 겹침 30초 이내는 알리지 않음, 와이파이 같은 이름 다른 주소는 원래 있던 것, 다시 측정 후 1단계 복귀.

## 구현하는 사람에게 맡기는 것

- 묶음 계산을 두는 위치(새 core 파일 권장)와 이름.
- 연습 모드에 주소가 바뀌는 가상 기기를 넣을지 여부.
- 화면 문구의 세부 표현.

## 알고 가는 한계

- 빈 교실에 있던 기기와 같은 생김새의 기기를 맞바꾸면 알 수 없다.
- 이름도 회사 코드도 내보내지 않는 기기는 `종류 모름` 한 묶음으로 개수만 비교한다.
- 블루투스·와이파이를 모두 끄고 LTE/5G만 쓰는 휴대폰은 여전히 보이지 않는다.
- 30초·15초·2분, 그리고 꺼진 아이폰이 `나의 찾기 신호`로 보인다는 해석은 실기기로 확인하지 않은 값이다.
